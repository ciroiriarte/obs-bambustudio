# obs-bambustudio — Bambu Studio packages for Linux distributions

[![upstream bump](https://github.com/ciroiriarte/obs-bambustudio/actions/workflows/upstream-bump.yml/badge.svg)](https://github.com/ciroiriarte/obs-bambustudio/actions/workflows/upstream-bump.yml)

Community/**unofficial** native packages of [Bambu Studio](https://github.com/bambulab/BambuStudio),
the 3D printing slicer, built **from upstream source** on the
[openSUSE Build Service](https://build.opensuse.org/project/show/home:ciriarte:bambustudio).
New upstream stable releases are picked up and rebuilt automatically.

  "Public Beta" pre-releases are skipped)

## Install

### openSUSE (zypper)

```sh
REPO=openSUSE_Slowroll
BASE="https://download.opensuse.org/repositories/home:/ciriarte:/bambustudio/$REPO"
sudo zypper addrepo -f "$BASE/home:ciriarte:bambustudio.repo"
sudo zypper --gpg-auto-import-keys refresh
sudo zypper install bambustudio
```

Run it with `bambu-studio` or from the desktop menu.

### Printer camera / live view

Live view uses GStreamer and FFmpeg's `libavcodec`. openSUSE's own FFmpeg
build omits patent-encumbered decoders such as H.264, so camera streams may not
decode. If so, install the full codecs from [Packman](https://en.opensuse.org/Additional_package_repositories#Packman)
(`libavcodec61` / `gstreamer-plugins-libav`). Slicing and printing are unaffected.

### Bambu Network Plugin

Cloud/LAN printer control relies on Bambu Lab's proprietary network plugin.
It is **not** part of this package; Bambu Studio offers to download it on first
use, as on any other platform.

## How the build works

Upstream builds its third-party libraries with a CMake superbuild
(`deps/CMakeLists.txt`) that **downloads ~23 tarballs at build time** and links
everything statically. OBS build workers have **no network**, so the project is
split into two OBS packages:

| Package | Published | Contents |
|---------|:---------:|----------|
| `bambustudio-deps` | no (build-only) | upstream's superbuild run offline: Boost, TBB, OpenVDB, CGAL, OCCT, OpenCV, Assimp, the bambulab wxWidgets fork, … installed as static libraries to `/opt/bambustudio-deps` |
| `bambustudio` | yes | the slicer, `BuildRequires: bambustudio-deps = %{version}`, linked statically against it; GTK3, WebKitGTK 4.1, GStreamer, OpenSSL and FFmpeg come from the distribution |

How `bambustudio-deps` stays offline:

1. `tools/gen_deps.py` configures upstream's superbuild (configure only) with
   the spec's `%deps_cmake_flags`, reads the download scripts CMake
   ExternalProject generates, and writes one `SourceNNN:` line per tarball into
   the spec (`<url>#/dep__<Dir>__<file>`).
2. OBS's `download_files` service fetches those URLs.
3. `%prep` copies each into `deps-dl/<Dir>/<file>`, where ExternalProject looks;
   it verifies **upstream's own SHA256** and skips the download.
4. The wxWidgets fork, which upstream clones unpinned from `master`, is
   replaced by a tarball of a pinned commit (`%wx_commit`, the fork's `master`
   at the upstream release date).

Guardrail: `gen_deps.py` aborts if upstream adds another git-cloned dependency or
a download without a SHA256, so a bump cannot silently produce a recipe that
needs network.

Deviations from upstream's dependency set:

- **FFmpeg** is not built; the distro's FFmpeg 7 `libavcodec` is used (upstream
  links it dynamically anyway). This also keeps patent-encumbered codecs off OBS.
- **OpenSSL** is not built (upstream bundles EOL 1.1.1k); the distro's OpenSSL 3
  is used, so TLS fixes arrive through normal distro updates.

The split means a fix to the slicer recipe rebuilds only `bambustudio`; the
multi-hour dependency build runs only when the version or dependency recipe
changes.

## Repository layout

```
packages/
  bambustudio-deps/          # build-only helper (publish disabled)
    _service                 # OBS: recipe from this repo (obs_scm) + download_files
    _constraints             # disk/memory for 22 static dependency builds
    bambustudio-deps.spec    # Source list generated by tools/gen_deps.py
    bambustudio-deps.changes
    bambustudio-deps-rpmlintrc
  bambustudio/               # the published package
    _service, _constraints, bambustudio.spec, .changes, -rpmlintrc
project/
  _meta.xml                  # repository/arch matrix   (osc meta prj -F)
  _config                    # prjconf                  (osc meta prjconf -F)
  bambustudio-deps.meta.xml  # package meta: publish disabled
  bambustudio.meta.xml
tools/
  gen_deps.py                # regenerate the deps Source list from an upstream tree
  bump.py                    # upstream release tracker (run daily by CI)
.github/workflows/upstream-bump.yml
```

## Maintainer workflow

### One-time OBS setup

```sh
P=home:ciriarte:bambustudio
osc meta prj     $P -F project/_meta.xml
osc meta prjconf $P -F project/_config
osc meta pkg $P bambustudio-deps -F project/bambustudio-deps.meta.xml
osc meta pkg $P bambustudio      -F project/bambustudio.meta.xml

# Each OBS package holds only _service + _constraints; the service pulls the
# recipe from this repo (main) and the tarballs from upstream.
for pkg in bambustudio-deps bambustudio; do
  osc co $P $pkg && cp packages/$pkg/{_service,_constraints} $P/$pkg/
  (cd $P/$pkg && osc addremove && osc commit -m "Source the recipe from GitHub")
done
```

### After changing a recipe

Push to `main`, then re-run the services:

```sh
osc service remoterun home:ciriarte:bambustudio bambustudio-deps
osc service remoterun home:ciriarte:bambustudio bambustudio
```

(or run the *upstream bump* workflow manually with `runservice` ticked).

### Bumping upstream

Automatic: `.github/workflows/upstream-bump.yml` runs daily. When upstream
publishes a newer stable release it runs `tools/bump.py` (regenerate deps
sources → pin wxWidgets → bump both specs and `.changes`), pushes to `main` and
fires the OBS runservice token for both packages.

Manual: `tools/bump.py [--version 02.08.02.61]`, review, commit, push, then
re-run the services as above. `tools/bump.py --dry-run` only reports.

Token setup (no OBS password lives in GitHub):

```sh
osc token --create --operation runservice home:ciriarte:bambustudio
gh secret set OBS_SERVICE_TOKEN     # paste the token string
```

If `gen_deps.py`'s guardrail trips on a new release, the run fails (GitHub
emails you); adapt the spec's `%prep` to the new upstream dependency and re-run.

### Local test build

```sh
osc co home:ciriarte:bambustudio bambustudio-deps && cd home:ciriarte:bambustudio/bambustudio-deps
osc service manualrun        # or: osc service runall
osc build openSUSE_Slowroll x86_64
```

Expect ~25 GB of disk and a few hours for `bambustudio-deps`.
